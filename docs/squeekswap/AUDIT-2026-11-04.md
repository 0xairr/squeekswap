## Web — findings fixed in this review

| Finding | Fix |
|---|---|
| A filled offer without a recorded fill time would be silently left out of Seeds | Targeted `OfferFilled` lookup by offer ID during refresh |
| Uncached artwork renders (~200 ms CPU each) were unbounded; one script could pin the CPU | At most 4 concurrent renders, 64 queued; beyond that the original art is served uncached |
| Bursts fanned out unbounded calls to `api.squeekchain.com`, which sheds load (503 at 40 concurrent) | At most 6 concurrent upstream calls; one retry for an incomplete answer |

Burst test, 150 uncached artworks at once: 58/150 succeeded before, 149/150 after; other routes stayed at 6–40 ms.

## Seeds review

- Scoring is pure and deterministic (`lib/seeds.ts`, 12 tests). A Zoomies result moving from pending to settled changes only the multiplier, never caps or cooldowns, so recomputed history is stable.
- Zoomies data is onchain (`RoundRecorded` only for rounds with wheel work; `BatchSettled` for finality).
- Known limit: someone with many wallets and many Genesis NFTs earns more. The per-NFT cooldown bounds earnings by real NFTs held, not wallets. Seeds are not Aura.

## Cloudflare deployment blockers

| Item | Status | Plan |
|---|---|---|
| `sharp` (native) for artwork thumbnails | Will not run on Workers | Replace with a WebAssembly SVG renderer (resvg-wasm) and cache results in R2 or the Cache API |
| Artwork render CPU (~100–200 ms) | Exceeds the Workers free-plan CPU limit (10 ms) | Workers Paid plan, or pre-render thumbnails into R2 |
| Indexer cache file (`node:fs`) | Writes fail gracefully; each isolate rescans | Acceptable now; move to KV/D1 later |
| In-memory rate limits and caches | Per isolate, so weaker | Add Cloudflare WAF rate-limiting rules for `/api/*` |
| Subrequest limits | Holdings for very large wallets use up to 100 upstream pages | Fine for current wallets (largest needs 11); revisit on the free plan |

## Post-launch audit (www.squeekswap.xyz)

Live system on Vercel, re-checked after the domain went live.

| Finding | Fix |
|---|---|
| `/api/genesis/holdings`, `/api/squeeks/[id]`, `/api/wheel` always returned 502 (Squeekchain's API challenges cloud servers) and were unused | Removed; the browser reads holdings and wheel status directly |

| No robots.txt, sitemap.xml or Permissions-Policy; llms.txt not Markdown-with-links | Added |
